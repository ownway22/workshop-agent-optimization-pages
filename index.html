    導覽¶

    情境¶

    Caldova 是一家虛構的製藥公司，公司內部提供 遵守差旅政策、回答夠快、成本合理 的差旅助理 Agent，協助員工處理差旅規劃與費用核對。Contoso Travel 是替它建置助理的虛構供應商。AI 開發團隊使用 Microsoft Foundry 與 GitHub Copilot，讓差旅助理從「能運作」走向「有證據地變好」。差旅助理 Agent 要同時滿足：

    • 旅客 Krystal：需要實用、快速，而且 不違反政策 的差旅協助。
    • 財務長 Andre：需要能說明 品質、速度與費用取捨 的數據。
    • 架構師 Lydia：需要新模型推出後，仍能 持續改善 Agent 的流程。


    目標¶

    能力強的前沿模型 是起點，不是永久答案。模型、價格與需求會持續改變；我們需要的是能重複使用的改善系統，而不是一次猜中「最好的模型」。本場的主軸是 Hill climbing：

    觀察 → 理解 → 衡量 → 只改一件事 → 重新測試 → 決定 → 重複上述動作。

    每次變更都用相同的測試題目（golden testset）、評分表（scorecard）與評分模型（LLM-as-a-judge）比較。只有在差旅政策與品質維持水準時，更快或更便宜才算進步。

    核心技術¶

    本場以 Foundry Hosted Agent 為執行基礎，搭配四項改善功能。

    功能 Act 用途 路徑
    Foundry Hosted Agent Act 1：先讓它運作 以 Microsoft Agent Framework 為框架，本機開發，部署至雲端使用。 Foundry → contoso-travel
    Agent Insights Act 2：找出表現不佳的地方 讀取大量追蹤記錄（Trace），將反覆出現的問題歸納成淺顯易懂的發現。 Foundry → contoso-travel → Insights
    Rubric Evaluator Act 3：讓它更好 根據 v1 的追蹤記錄與 Insights 發現草擬評分表，再以相同方式評分每個版本。 Foundry → Evaluations
    Model Router Act 3：讓它更好 透過單一部署，為每個請求選擇合適的模型。這就是 v2。 Foundry → Models → model-router
    Agent Optimizer Act 4：擴大改善規模 提議調整行為指示（instructions），並用練習題試跑。由你審查並決定是否採用。 Foundry → contoso-travel → Optimize

    這些功能環環相扣——Insights 告訴你哪裡出了問題、Rubric Evaluator 將問題轉成量身訂定的評估方式、Model Router 自動選擇合適的模型、Agent Optimizer 則探索值得驗證的 Agent 候選設定。
