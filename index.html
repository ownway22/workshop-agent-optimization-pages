    導覽¶

    Travel Agent 的改善計畫：使用 Microsoft Foundry 與 GitHub Copilot，讓旅遊助理從「能運作」走向「有證據地變好」。

    第一場 Factory 聚焦多 Agent 協作；第二場回答企業導入問題：這個助理是否值得採用，改版後是否更有價值？ 我們保留 Travel 原始案例，用「設備維護資訊助理」作半導體產業對照，練習查核依據、回應效率與費用取捨；沿用 VM 與學員帳號，但不沿用 Factory 的程式、資料或後端設定。

    開始：準備本組環境 先看核心概念

    課堂命令尚須按組放行

    先確認本組目前可操作範圍。教材可閱讀不代表雲端已就緒；未放行時使用經核對的本組預跑證據，沒有證據就如實記錄尚未完成。

    這次要解決什麼問題？¶

    Caldova 是一家虛構的製藥公司，需要一位遵守差旅政策、回答夠快、成本合理的旅遊助理。Contoso Travel 是替它建置助理的虛構供應商。

    • Krystal，旅客：需要實用、快速，而且不違反政策的差旅協助。
    • Andre，財務長：需要能說明品質、速度與費用取捨的數據。
    • Lydia，架構師：需要新模型推出後仍可重複使用的改善流程。

    能力強的模型（model）是起點，不是永久答案。新模型、價格與需求會持續改變；我們需要的是能重複使用的改善方法，而不是一次猜中「最好的模型」。

    本課程的主軸是 hill climbing：

    觀察 → 理解 → 衡量 → 只改一件事 → 重新測試 → 決定 → 重複。

    每次變更都用相同的 Testing 題目、評分表（scorecard）與評分模型（judge）比較。只有在差旅政策與品質維持水準時，更快或更便宜才算進步。

    回到半導體團隊，清楚的資料依據與限制，才有助於接手者判斷是否需要重查；一致的比較方式，才讓工程、營運與 IT 能討論同一項取捨。本場練習的是這套驗證方法，不是已接入工廠的解決方案；可延伸量測的業務效果另與課堂證據區分。

    四個 Act 的操作路線¶

    階段 要回答的問題 主要功能與產出
    Act 1：先讓它運作 助理先能幫使用者完成哪件有用的事？ 課前由講師備妥 Hosted Agent v1；課堂確認本組基準與能力範圍。
    Act 2：找出表現不佳的地方 哪些失誤會造成重查、重做或交接不清？ 收集重複提問的執行追蹤記錄（trace），讓 Insights 找出反覆問題。
    Act 3：讓它更好 更快或更省，是否犧牲了必要品質？ 審閱固定的 Rubric Evaluator 評分表，用同一課堂題組比較 v1 與 Model Router v2。
    Act 4：擴大改善規模 如何多做嘗試，又保留人的掌控？ Agent Optimizer 提出 Agent 行為指示（instructions）的候選方案，再由人審查、重新測試與決定是否上線。

    學習目標¶

    • 用工具回傳結果（tool result）與執行追蹤記錄核對 Agent 的行為，不只看回答是否流暢。
    • 將 Insights 的發現轉成符合業務需求的評分表。
    • 區分模型、行為指示、工具與資料的變更，一次只測一件事。
    • 維持 Exploring、Training、Testing 題目的隔離，避免把熟悉的題目誤當成進步。
    • 讓 Agent Optimizer 多做嘗試，但保留人的審查與發布決策。
    • 將比較結果說成業務取捨，並提出一個回到公司後可驗證的小型改善假設。

    怎麼使用這份教材？¶

    先確認本組環境與分工，再沿各幕的編號步驟操作、核對畫面並保存結果。每組輪換當輪操作者、證據檢視者、評分／指示檢視者與紀錄者；不是所有人同時提交工作。兩小時的建議節奏不保證雲端工作在固定時間完成。

    標示 操作界線
    學員操作 · 必做 依主線核對本次結果與證據；未獲准呼叫模型時，閱讀講師提供的結果，不宣稱自己已執行。
    講師課前準備 收合的環境建置與耗時作業，由講師或資源負責人事前完成。
    原版延伸閱讀 Fine-tuning、Quality Router 等不屬於本場操作範圍，不在共用環境執行。
    需授權／可能計費 先確認身分、Travel 環境、費用與影響，不因教材有指令就執行。

    閱讀教材使用學員筆電瀏覽器；現場命令只由當輪操作者，在主要 Ubuntu VM 的第二場專用 Terminal、專案根目錄執行。Act 1 是課前基準，現場主線為 Act 2–4。完成條件是自行核對清單，本站不儲存完成進度。

    呼叫模型、評分、Insights 與 Agent Optimizer 可能產生費用。不執行原版 setup／teardown，不刪除上一場資源；課後由指定資源負責人處理。

    讓 GitHub Copilot 帶你逐步閱讀

    將以下 prompt 貼到 Copilot Chat。它可以協助說明，不代表獲得操作雲端資源的授權。

    請依照 Travel Agent 的改善計畫，從「準備」開始，一次帶我完成一個步驟。
每一步先說明目的與 hill climbing 的關係，確認本組已放行，再解釋本場交付的指令。
等我貼上結果後，解釋實際產出、注意事項與下一步。
不要照搬原版 setup／teardown，不自行提交雲端工作或切換上線版本。

    環境架構¶

    同日活動的共通環境示意，不是本次部署證明。圖中的 Multi-agent／RAG／MCP 是平台能力示意，不表示第二場全部都會實作；本場聚焦一個 Travel Hosted Agent 的評估與最佳化。開啟原圖。
