    Act 4：擴大改善規模¶

    目標¶

    讓 Agent Optimizer 提出 Agent 行為指示（instructions）的調整，用練習題（practice）挑選候選方案（candidate），再用相同 Testing 題組重新驗證。自動化不應跳過人工審查，也不應讓未驗證的版本意外上線。這一步的業務意義，是讓改版有理由、審查有依據、決策可追溯；有效比較後保留原版，與證據不足而尚不能決策，也要分清楚。

    步驟¶

    1．核對本輪工作¶

    在本組 Foundry 的 contoso-travel → Optimize 或已交付的 status 輸出中，證據檢視者核對起始標籤／實際版本、工作 ID、12 道練習題、評分表與完成狀態。取消、失敗或狀態不明就記錄並停止，不因看到候選方案名稱就執行 apply。

    2．開啟真實差異¶

    本輪已有有效候選方案並獲准下載後，當輪操作者在 VS Code Explorer 對起點保留的行為指示檔案選 Select for Compare，再對本輪候選檔案選 Compare with Selected。指示檢視者逐項說明變更對應哪項有效分析發現／追蹤記錄；只讀取差異，不覆寫基準或自行接受全部變更。

    3．重測並作決定¶

    只有候選方案、部署與實際版本均通過檢核，才接續 Step 11。紀錄者將相同六題一次的結果整理成比較紀錄，全組提出發布或保留理由，再交由獲授權者決定是否切換。沒有有效候選方案時就記錄阻礙，不製作假差異畫面或分數。

    完成條件¶

    以下為自行核對清單，本站不儲存完成進度。

    • 能指出 Agent Optimizer 起點、候選方案與其處理的 Insights 問題。
    • 已區分 12 道練習題、課堂六題一次與完整 24 題三次，不混用其分數。
    • 能說明建立版本、Foundry 顯示 promoted 與端點上線的差別。
    • 有保留或發布的實際證據與理由；未執行的部署、選做或切換不算已完成。
    • 理解授權者決定是否上線，並維持題組隔離與單步實驗契約。

    疑難排解¶

    狀況 下一步
    工作只有提交、尚未完成 記錄目前狀態，不重複提交，也不宣稱已取得候選分數。
    練習題提升但 Testing 未維持 保留已驗證的版本，不以示範分數取代本次結果。
    部署中斷或操作網站版本不符 由獲授權者確認原先使用中的版本標籤，再依疑難排解處理。
