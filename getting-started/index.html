    準備¶

    本場接續 Factory。沿用同一台 Ubuntu VM 與學員帳號，但使用第二場專用的 VS Code 啟動環境、工作目錄與本組 Foundry 專案。 不需要重新 Fork、建立 Codespaces 或重建上一場環境。

    學員閱讀方式¶

    自己的筆電瀏覽器用來閱讀教材及進入遠端桌面；Ubuntu 桌面內的瀏覽器用來開啟本組 Travel 操作網站與 Microsoft Foundry。教材與操作網站的正式連結均由講師交付，不從本機預覽的連接埠推測活動入口。

    頁內目錄整合於左側導覽，窄視窗請開啟頁首選單。閱讀教材不需要安裝 MkDocs 或啟動網站服務。

    本場使用的環境¶

    項目 本場安排
    沿用 上一場的 VM、遠端桌面入口、學員 Entra 帳號與分組。
    VS Code 使用講師交付的 Agent Optimization - VS Code 專用捷徑；不要從上一場的 VS Code 視窗直接執行本場命令。
    專案 第二場獨立的工作目錄與 Python 環境，不是 Factory 的 repository 或網站目錄。
    雲端 使用講師交付的本組 Foundry 專案、contoso-travel Agent、監控與 Travel 操作網站，不借用其他組的資源。
    azd 環境 使用交付的 AZURE_ENV_NAME；環境名稱須與本組交付單相符，不自行猜測或照抄其他組。
    共用操作 每組一台主要操作 VM／工作副本，一次只有一位當輪操作者提交付費工作或部署。
    課堂範圍 Act 1 的基準由講師課前準備；現場主線是 Act 2–4。

    本場模型，不照搬原版部署清單¶

    模型部署（deployment） 本場用途
    gpt-5 v1／v3、Insights 分析與 Agent Optimizer 推理。
    gpt-5-mini 評分表產生、評分與 Agent Optimizer 評估。
    gpt-5-mini-byok 本組 VS Code Chat 與輔助工作，不與評分部署混用。
    model-router v2；Balanced routing 僅允許 GPT-5、GPT-5-mini、GPT-5-nano。

    本場不執行模型微調（fine-tuning）或 Quality Router，也不建立原版的 GPT-5.4 系列或 insights-judge 別名。 原版延伸路線只作參考閱讀。

    容量由講師管理。Azure capacity 是模型／SKU 對應的原始單位，不能一律當成「千 tokens／分鐘」，也不要自行調額、改模型或更換區域。

    進場檢核¶

    1. 進入原本被指派的 Ubuntu 遠端桌面，開啟第二場專用 VS Code 捷徑與 Terminal。
    2. 確認講師交付的本組專案、Travel 操作網站、主要操作 VM 與 azd 環境。
    3. 由本人依講師放行完成本場登入與 BYOK 檢核。在 Chat: Manage Language Models 使用交付的 Azure 模型端點與 gpt-5-mini-byok，不填 Foundry 專案端點；key 只透過 SecretStorage 輸入，不貼入 Chat、Terminal 或教材。不複製上一場或教師的登入快取、keys 或整個 .azure/。

    4. 在第二場專案根目錄確認環境名稱。這個檢查只讀取已交付的非秘密變數，不代表雲端已就緒：

      printf '組別：%s\n環境：%s\n' \
  "${WORKSHOP_GROUP_ID:?請先完成本組環境交付}" \
  "${AZURE_ENV_NAME:?請先完成本組環境交付}"

      組別與環境須與本組交付單相符。缺值或分組不符時停止，請講師處理，不自行設定或借用其他組環境。 5. 確認講師已宣布本組哪幾項操作可執行，再進入付費工作或部署步驟。

    核對完成後，紀錄者留下本組環境、主要 VM、當輪操作者、Travel 操作網站／Foundry 入口、使用中版本與結果來源。只存放在講師指定的受控位置，不將帳號識別資料、金鑰或完整執行追蹤記錄（trace）貼到公開教材。

    命令的執行位置與授權

    課堂命令只由當輪操作者，在主要 VM 的第二場專用 Terminal、專案根目錄執行；該目錄可看到 infra/、src/、data/ 與 azure.yaml。不是自己的筆電 Terminal，也不是網站的 workshop-pages-mkdocs/ 目錄。命令明確傳入本組 AZURE_ENV_NAME，但環境變數存在不等於取得操作授權。

    課堂操作放行¶

    教材公開不代表雲端環境已就緒，也不代表取得操作授權。 本站不即時探測各組狀態；課堂以講師當日交付的版本、可操作項目與核准範圍為準。

    進入操作前要確認 未符合時怎麼做
    本組來源版本、專用 Client 與本人登入已完成交付。 停在環境確認，不自行重建；本機測試或其他組成功不能代替本組驗收。
    基準標籤、回應實際版本及證據來源一致。 保留原始紀錄；版本不符或不明的結果須隔離，不列入比較。
    本輪 Insights 的追蹤記錄、時間範圍與費用已核准。 保留失敗或缺資料狀態，不自行重送、擴大配額或以抽樣冒充完整分析。
    Optimizer 工作有效且已完成，候選方案有明確來源。 取消、失敗或狀態不明就停止；沒有新核准，不再次提交、套用或部署。
    當輪操作者與工作排程已確認。 不從多台 VM 重複提交；先向講師確認本組可執行範圍。

    被阻擋時，先使用講師交付的可驗證、已去識別化的本組預跑結果，註明時間、版本與來源。沒有可用的預跑結果就標記「尚未完成」，不拿其他組或原版影片的分數代替本組結果。排查方式見疑難排解。

    題量與公平比較¶

    用途 題量／重複次數 使用方式
    課前完整探索 36 題 × 3 次，共 108 個回答 建立基準行為與追蹤記錄；不是全員在課堂各跑一次。
    課堂探索 BLOCK、EVIDENCE、HERO、ACCESS 各一次 依講師放行，循序操作四個代表情境；不是完整探索。
    完整評估 full 24 題 × 3 次，共 72 個回答／版本 課前預跑，保留題集、評分表、評分模型與實際版本。
    課堂評估 classroom 6 題 × 1 次／版本 Testing 題集各難度依順序取前兩題；使用 --cohort classroom，不是任取六題。
    Agent Optimizer 練習題（practice） 12 道 Exploring 練習題、3 個候選方案 不使用 Testing 題目；候選方案仍要重新做相同評估題組的評分。

    六題一次的分數不能與 24 題三次直接混比。 同一比較中的題目、重複次數、評分表版本、評分模型與實際回應版本必須一致；缺少證據或版本混用的結果不納入比較。source.type: local 指評分使用已擷取的回答，仍會呼叫付費評分服務，不是離線免費評分。

    分工、交接與安全¶

    • 當輪操作者：在主要 VM 執行本輪核准命令；同組一次只有一個重工作，不重複提交。
    • 證據檢視者：核對追蹤記錄、回應 ID、實際版本與來源。
    • 評分／指示檢視者：審查評分表或 Agent 行為指示差異，不自行改動共用評分依據。
    • 紀錄者：保存題量、工作狀態、結果路徑與決策；切換角色時一併交接。

    其他組員可在個人 VM 閱讀受控匯出的非秘密結果及準備提案。付費工作依講師排程，不在多台 VM 複製可寫狀態後並行提交；若要更換主要 VM，先停止提交並完成狀態交接，由新操作者本人登入。

    兩小時建議節奏¶

    時段 小組要完成的事 帶到下一步的紀錄
    進場 10 分鐘 完成準備與 Act 1 基準確認。 分工、本組環境與 v1 實際版本。
    Act 2，25 分鐘 四個代表情境、追蹤記錄與 Insights 證據；只提交已放行工作。 一項有追蹤記錄依據的問題，或明確阻礙。
    Act 3，35 分鐘 審閱評分表、核對六題一次的 v1／v2 比較。 同一評估題組的比較紀錄與採用建議。
    Act 4，40 分鐘 審查有效候選差異、核對重測結果。 候選來源、實際版本與發布／保留理由。
    收尾 10 分鐘 完成回顧及在途工作交接。 兩分鐘摘要與下一個單步實驗。

    這是課堂安排，不是雲端完成時間承諾。工作尚未完成就註明狀態；講師有交付可驗證的本組預跑證據時才使用，沒有證據不補造結果。

    不重建、不整組清理

    本場沿用上一場的共用資源群組。不要執行原版整套 setup／teardown，不刪除、覆寫或調降上一場資源。權限、模型容量、環境建置與課後清理由講師或指定資源負責人處理。

    完成條件是自行核對，本站不儲存進度。
