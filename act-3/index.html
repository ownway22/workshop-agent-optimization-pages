    Act 3：讓它更好¶

    目標¶

    用同一份評分表（scorecard），衡量一次只改一件事的實驗，並保留有證據的進步。審閱 Rubric Evaluator 根據探索證據產生、且由講師凍結版本的評分表；用相同課堂題組比較 v1 與 Model Router v2。本場不執行模型微調或 Quality Router。

    這一步在 hill climbing 的位置¶

    這一步的業務意義，是支援「是否值得採用」的討論；不是把速度、Token 用量或平均分數的排名直接當成營運價值。

    步驟¶

    1．審閱評分依據。¶

    在本組 Foundry 的 Evaluations → Evaluators 開啟講師交付的 evaluator ID 與版本，不只憑名稱判斷。評分檢視者將政策、查證、金額與誠實揭露面向各對應到業務指引或有效的 Insights／追蹤證據；缺少依據時先記錄，不自行改評分表。

    2．取得同一條件的結果¶

    本組放行後，當輪操作者取得六題一次的 v1／v2 評估；其餘組員核對題組、評分表、評分模型與回應實際版本。工作未完成或版本不符時停下來，不重送以補出比較表。

    3．寫下採用理由¶

    使用比較紀錄，留下品質、最弱面向、延遲、Token 用量與來源。每人提出一個支持或反對採用 v2 的證據；本幕不切換共用端點。

    完成條件¶

    以下為自行核對清單，本站不儲存完成進度。

    • 能將評分表的業務面向追溯至指引與 Insights。
    • 已核對本次 Testing 題組、評分模型與評分表一致。
    • 能指出 v2 相對 v1 的唯一變更，以及政策與最弱面向是否維持。
    • 已記下採用、保留或證據不足的理由；沒有將被隔離的 Router 結果列入比較。
    • 未把 Token 用量當成完整費用，也未把未執行的選做實驗當成自己的分數。

    下一步¶

    進入：Act 4：擴大改善規模。

    疑難排解¶

    狀況 下一步
    評分表有已知行為指示警告 檢查實際面向與原指南的提示來源，不只為隱藏警告而重建。
    缺少標籤或分數 確認該版本是否已建立、評分是否完成；不要自行猜版本編號。
    題量、評分表、評分模型或回應版本不一致 不混算分數；保存原始證據，由講師確認後再重新驗證。

    詳細處理方式見疑難排解。
