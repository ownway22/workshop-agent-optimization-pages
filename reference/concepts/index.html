    核心概念¶

    看懂版本、執行追蹤記錄與題組，才不會把一次好回答誤認為可持續的改善。以下詞彙以繁體中文說明；產品名稱、介面標籤、檔名與 CLI 參數保留原文，方便對照實際操作。

    四幕改善流程¶

    四幕流程示意；本場 Act 1 是講師課前基準，課堂主線是 Act 2–4。點擊圖片可放大，以 Esc 或關閉按鈕返回。這不是已部署環境、實際分數或執行結果。

    Hill climbing：用同一個高度計¶

    這張原版概念圖包含學生模型支線；本場只操作 v1、Balanced Router v2 與行為指示候選方案 v3，不執行模型訓練。圖的位置不表示實際分數或勝出版本；點擊可放大。

    1. 知道起點：用固定評分表與 Testing 題組評分 v1。
    2. 只走一步：只改模型、行為指示或工具／資料中的一項。
    3. 用同一個高度計：Testing 題組、評分表與評分模型都保持一致。
    4. 往上就保留，不然退回：結果不符合需求時，維持已驗證的版本。
    5. 重複：下一個實驗也要有明確起點與獨立比較。

    向下的一步不是沒用：它會告訴我們，對這個工作負載而言，哪個方向不值得直接採用。

    常用詞彙¶

    詞彙 在本課程的意思
    Agent 透過模型、行為指示與工具處理旅遊需求的助理。
    模型（model） 產生回答、判斷或工具呼叫的 AI 模型；不是 Agent 的版本標籤。
    基準版本（baseline） 每次實驗要拿來比較的起點，不一定永遠是 v1。
    候選方案（candidate） 待審查、部署與重新評估的變更提案，不等於已上線版本。
    Agent 行為指示（instructions） 規範 Agent 如何處理需求與使用工具的內容；不是要在 Terminal 執行的命令。
    工具回傳結果（tool result） 工具實際回傳的結果；不能用 Agent 的樂觀敘述取代它。
    執行追蹤記錄（trace） 一次回答的逐步紀錄：工具呼叫、回傳結果、延遲與 Token 用量。
    延遲（latency） 一次回答所花的時間，與評分服務的處理時間分開看。
    Token 用量（tokens） 模型處理與產生文字的用量，不是完整帳單。
    Insights 分析發現（findings） 從大量執行追蹤記錄歸納的反覆問題與證據。
    評分表（scorecard） 本課程對 Rubric Evaluator 的稱呼；包含評分規準（rubric）的面向與權重，對應業務與政策需求，版本依本組凍結的 evaluator 記錄。
    評分模型（judge） 依固定評分表判讀回答的模型，本場使用 gpt-5-mini。
    Model Router 透過單一模型部署，為每個請求選擇模型。
    教師／學生模型（teacher／student） 原版延伸路線的回答提供者與受訓模型；本場不執行。
    Agent Optimizer 提出行為指示候選方案，以練習題試跑；不取代人的發布決策。

    請求與證據的責任分工¶

    想讓團隊少一點猜測，先分清楚誰回答、誰查資料、誰保留證據、誰決定採用。模型提出工具呼叫，由 Hosted Agent 裡的程式執行；Copilot 輔助工程工作，不是旅遊請求的執行核心。

    展開：本場執行與證據架構

    靜態責任圖，依本場程式與流程整理；不是即時部署或放行狀態。Agent Framework／Responses 負責 Agent 執行，FastAPI 操作網站呈現回答及工具證據；Application Insights／Log Analytics 保留觀測資料，評分則使用擷取的實際回答與凍結評分表。圖中的箭頭不代表這些工作會自動連續執行。

    實際請求要核對回應的執行版本；分析還要核對時間窗與來源；評估要固定題組、評分表及評分模型。網站有畫面，不等於這三項都完成。

    展開：八個工具與資料邊界

    下列六類共 8 個工具。它們讓案例能重複核對，不是連接真實航空公司或工廠系統的服務：

    類別與數量 做什麼 解讀結果時的邊界
    搜尋，3 個 查詢航班、飯店與租車選項。 只查合成庫存，不是即時票價、空房或車輛供應。
    查價，1 個 依既有資料 ID 取回價格與屬性。 不是外部即時報價；固定匯率是為了重複核對，不是金融行情。
    政策，1 個 依範例規則判斷並回傳政策依據。 涵蓋工具已實作的規則，不是完整企業合規引擎或真實核准。
    收據，1 個 依收據 ID 或對應檔名讀取結構化 JSON，檢查費用項目。 不是通用 OCR；找不到固定資料就回報錯誤，不能推論已能處理任意收據圖片。
    行程組裝，1 個 組合已選項目與估價。 目前每筆飯店只加一晚、租車只加一天；收據不併入估價，不能直接視為完整多日或含報銷總價。
    模擬預訂，1 個 依行程與政策檢查結果，回傳模擬接受或拒絕。 真實預訂被停用；模擬成功不等於出票、付款或企業工作流程已執行。

    固定資料與工具不代表模型的選擇、推理與回答必然固定，所以仍需重複觀察及公平比較。閱讀本機教材不需 Azure；執行線上 Agent、評分或分析仍需真實服務，現場與預跑結果要分開標示。

    對照設備維護資訊助理，可轉移的是「查明資料與工具契約，再判讀輸出」的方法；這張表不表示本場已具備設備知識檢索、派工或設備控制功能。

    版本、標籤與端點¶

    • 版本（version）：一次部署的不可變快照，包含該次的模型、行為指示與設定。
    • 標籤（label）：方便辨識變更的名稱，例如 v1、v2、v3；腳本記住它對應的實際版本。
    • 端點（endpoint）：同一個 Agent 的固定 URL；使用中版本（active version）決定預設流量由誰回答。

    部署新版本不會覆寫舊版，也不是建立第二個端點。版本編號不等於標籤：假設 v1 標籤對應實際版本 2，不能因此把它稱為 v2。這只是編號示例；實際對應以本組交付紀錄為準。

    標籤 相對起點改了什麼 建立方式
    v1 起點，gpt-5。 講師課前建立與驗證。
    v2 相對 v1，只改模型為受限的 Balanced Router。 本組放行後，由當輪操作者執行 Script 08。
    v3 相對選定起點，只改人審查過的行為指示。 本輪已有有效候選方案且獲准後，執行 Script 11 deploy。

    其他標籤屬於原版延伸，不是本場需要建立的版本。標籤、請求參數與 CLI 成功都不能證明服務真的執行該版本；須以實際回應與執行階段紀錄核對。版本不符的擷取結果要隔離，不能換個標籤後繼續評分。

    評分和上線是不同操作

    腳本可明確呼叫某個版本評分，而讓操作網站繼續使用原版。go-live 才是切換使用中版本；切換後開新對話，避免把舊對話當成新版結果。部分腳本提供 --activate，未獲授權不要自行使用。

    三組題目，三種用途¶

    題組 題數 用途 不可以拿來做什麼
    Exploring 36，簡單／中等／困難各 12。 觀察 v1，產生 Insights 與評分表草擬依據。 代替最終 Testing 評分。
    Training 原版 48，含 40 train / 8 validation。 原版 fine-tuning 延伸；本場不執行。 混入本場 Testing 比較。
    Testing 完整題集 24，簡單／中等／困難各 8。 完整預跑用 24 題三次；本場課堂固定各難度前兩題，共六題一次。 混入 practice、training 或教 agent 背答案。

    Exploring 前 12 題標記為練習題（practice），包含操作網站的四個情境，供 Agent Optimizer 使用。Testing 使用其他題組未出現過的城市與收據，檢查是否能處理新情況。

    題集規模與重複次數都屬於比較條件。 full 的 24 題三次與 classroom 的六題一次分開保存，不能互相比高低。相同評估題組（cohort）還要固定評分表版本與評分模型；詳見本場題量。

    Testing 也要避免過度迎合

    同一題組是公平比較的基礎，但若持續根據 Testing 答案修改行為指示，仍可能過度迎合。不要把 Testing 題目加入 Agent Optimizer 的練習題或學生模型的訓練資料；新的業務需求也可能需要新的保留評估資料。

    比較時要看什麼？¶

    1. 先核對差旅政策與關鍵 hard gates，不能只看平均分數。
    2. 看最弱面向與簡單／中等／困難，避免少數好回答掩蓋退步。
    3. 檢查多輪差異，不把微小變化直接當成穩定提升。
    4. 分清楚品質、延遲、Token 用量與實際費用。模型價格、部署層級與其他 Azure 資源也會影響帳單。
    5. 每個比較都對照自己的起始版本，而不是只把標籤排成一張勝負表。

    補充：Repo 與編號怎麼對照¶

    主線先學會判讀與決策；需要追查資料或程式時，再展開下面的索引。路徑以主要 VM 的第二場專案根目錄為準，不是網站目錄。

    展開：常用檔案、用途與操作界線
    位置 用來找什麼 本場怎麼使用
    data/fixtures/ 合成庫存、政策、收據與匯率。 學員核對來源，不直接改資料追求高分；部署產生的複本不是修改來源。
    data/questions/ Exploring、Training、Testing 題集。 核對題目來源；課堂六題依既定規則選取，不將 Testing 轉成練習或訓練資料。
    data/scorecard-guidance.json 產生評分表時的業務指引。 指引不等於最後凍結的 evaluator；課堂審閱交付副本，不自行重新生成。
    src/agent/.agent_configs/ 基準與已下載候選方案的行為指示、模型設定。 閱讀本輪獲准檔案、比較差異；不覆寫基準或自行部署。
    src/agent/tools/ 八個工具的實作與契約。 有疑問先留證據交給負責人，本場不另開工具修改實驗。
    infra/、src/scripts/ 操作入口與擷取、評分、比較等輔助程式。 使用完成驗證並交付的本場入口；看到檔名不等於獲准執行。
    講師交付的本組受控匯出結果 回答、追蹤、評分表、比較與工作狀態。 學員讀去秘密副本；原始 .azure/<env>/ 留在主要工作副本，不散發整個教師部署目錄或登入快取。
