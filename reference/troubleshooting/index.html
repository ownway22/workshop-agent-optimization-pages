    疑難排解¶

    先確認你遇到的是「教材閱讀問題」還是「Azure lab 執行問題」。不要因為網站正常，就跳過 lab 的健康檢查。

    教材閱讀問題¶

    狀況 先做什麼
    窄視窗看不到左側 Act 目錄 開啟頁首選單；展開後選擇 Act 1 至 Act 4。
    圖片放大後不知道怎麼回來 使用右上角「關閉」按鈕或 Esc。桌面版可用「上一張／下一張」；窄視窗可滑動切換，使用鍵盤時可按左右方向鍵。
    搜尋沒有預期內容 使用完整詞 Foundry、Optimizer、「評分表」或「審查」，確認結果能跳到對應頁面；不要把縮成 Foundr 才找得到當成正常。回報完整查詢詞、預期頁面與目前網址。
    正式 Pages 出現缺圖、缺 CSS 或錯誤連結 回報正式 URL 與發生頁面，由維護者檢查 site_url、repository 子路徑與發布版本，不要求學員另起本機網站。

    網站維護者的安裝、build 與 gh-deploy 操作放在網站原始碼的 README，不屬於學員 lab。

    standard-1 保留中文斷詞，設定搜尋語言為 zh、en 並停用搜尋處理流程，避免詞幹處理導致完整術語漏搜。這是教材搜尋設定，不會修改模型或實作環境。

    鍵盤與圖片操作¶

    • 使用 Tab 到達頁首選單、搜尋與色彩控制項；Enter／空白鍵啟動按鈕，Esc 關閉搜尋或放大圖片。
    • 圖示應有可讀名稱與可見焦點；選單與搜尋開關應呈現正確展開狀態。
    • 小型 Travel 識別圖示不開圖片檢視器；流程示意圖可放大，但不代表實測結果。
    • 若無法操作，回報瀏覽器、縮放、是否啟用減少動態效果，以及實際按鍵，不用示意圖代替操作成功證據。

    Lab：交付或健康檢查失敗¶

    找不到第二場環境或登入失敗¶

    先回到準備確認第二場專用捷徑、工作目錄、本人登入與組別。缺少交付、來源尚未放行或本組登入失敗時，停下來請講師處理，不照搬原版 setup、suffix 或其他組環境。

    不要複製教師或上一場的登入快取、整個 .azure/ 或其他人的 VS Code 設定。網頁可開啟與工具可執行，都不等於已取得本組資料與課程操作權限。

    缺少模型、權限或執行階段授權¶

    保存錯誤、實際版本與本組環境名稱，交給講師。不要自建原版 insights-judge 別名、替換模型、擴大資源群組權限或執行整套補充基礎設施部署。

    版本已建立、但執行階段權限檢查失敗時，保留既有標籤；講師完成受控授權後，才按交付方式接續，避免重複部署。

    本組目前仍有驗證阻礙¶

    先查看課堂操作放行條件，再向講師確認本組當日可執行範圍。版本不符的結果須隔離，分析容量不足或 Optimizer 工作取消也不能自行重試；不以其他組成功、教材公開或本機測試通過推定本組已修復。

    Lab：提問或 Insights 有問題¶

    提問遇到速率限制¶

    停止重複提交，保存狀態與錯誤，交由講師核對本組容量及排程。不要自行增加配額、切換區域或反覆重試。逾時可閱讀已交付的可驗證本組預跑結果，但須標明來源，不能冒稱是本輪的新執行。

    Insights 無法啟動或沒有新的分析發現¶

    不要先重送工作。由證據檢視者確認：

    1. 本次 v1 追蹤記錄已送達，而且在分析時間範圍內。
    2. 交付設定選用本組 gpt-5，不是原版 insights-judge 別名。
    3. 操作者與專案受控識別的權限符合本場設定，並等候角色指派生效。
    4. 分析工作是失敗、仍執行中，還是成功但沒有分析發現。

    跨日或時間窗不符時，由講師核對要分析的追蹤記錄、版本與容量，再決定是否重新核准。增加時間範圍不是通用修正。詳細背景可讀原始疑難排解，但其中舊版部署與模型設定不是本場可直接照抄的操作。

    Lab：評分表與版本¶

    評分表顯示 Agent 沒有行為指示¶

    若是以下已知警告，請依 Act 3 的說明檢查評分面向：

    Generated with input-quality warnings: The agent has no instructions.

    不要為了隱藏這個警告而重建評分依據；真正的工作失敗仍要保留錯誤與排查。

    標籤還沒有建立¶

    出現 has not been built yet 時，先向講師確認該標籤對應的版本是否已建立。不要把 Foundry 的編號自行當成 v2 或 v3。

    回應實際版本與標籤／請求版本不符¶

    保存回應 ID、實際 agent_reference 與執行階段證據，隔離該筆結果並停止比較。請求用了 --version 或另外建立了對應版本的工作階段，都不能取代實際回應的驗證。

    課堂分數無法比較¶

    確認都是 classroom 的固定六題一次，且評分表版本、評分模型、擷取模式與來源組別一致。完整 24 題三次的結果另列，不混算；缺少資料或被隔離的結果不補成零分，也不從其他執行拼湊。

    Travel 操作網站顯示非預期版本¶

    先記錄應有的使用中版本標籤與實際版本，交由當輪操作者和講師核對，不用 go-live 掩蓋版本綁定問題。經核准切換後，重新整理網站並開啟新對話，再核對實際結果。

    Lab：Optimizer 取消、逾時或候選不可用¶

    • 已有 operation ID 或狀態不明時，只核對既有工作，不再次 submit。
    • 已取消的工作不自行恢復或重送；本組須取得新的明確核准。
    • 沒有有效候選，就不執行 apply、deploy 或 go-live。
    • 既有候選方案與預跑結果須附真實時間、起點、評分表、題集與版本，不把原版示範圖當成本組成果。
    • 本場不執行 fine-tuning、Quality Router 或其他延伸來繞過阻礙。

    怎麼提供有用的錯誤回報？¶

    保留指令、錯誤、UTC 時間、正在使用的標籤，以及已經完成的步驟。對外分享前，移除憑證、連線字串、存取權杖、帳號資訊與敏感追蹤內容；不要把存取權杖與前文的 Token 用量混為一談。
